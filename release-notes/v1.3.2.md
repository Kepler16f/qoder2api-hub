# v1.3.2 — 传输韧性与额度实时化

本版本聚焦两类"看不见但天天遇到"的问题：**上游网络抖动不再变成 502**、**账号剩余积分自动保持最新**。桌面形态、安装方式与 API 协议零改动（网关本体 1.2.17 → 1.2.19），五平台安装包已刷新。

> 说明：v1.3.1 曾作为内部构建（仅传输韧性修复，未公开发布），其内容已全部包含在本版本中。

## 🐛 上游传输韧性（网关 1.2.18）

此前上游网络短暂抖动时，客户端会收到 502，报错为 `transport transient: <urlopen error [WinError 10061] 由于目标计算机积极拒绝>`；更麻烦的是本机代理开关怎么调都无法恢复，只能重启应用。两处修复：

- **出站不再被"启动瞬间"的代理状态绑架**：`urllib` 的默认 opener 会在进程首次请求时把系统代理设置缓存到进程结束——代理软件随后退出或换端口时，全部上游调用会一直撞死在死端口上（WinError 10061），用户侧改注册表、开关系统代理都无效。现改为**逐请求实时解析代理状态**（`UpstreamOpener`），TUN / 系统代理 / 直连三种形态可随时切换、**无需重启进程**；特殊部署可用环境变量 `QD_PROXY_UPSTREAM_PROXY` 显式指定代理出口。
- **全池传输故障不再过早放弃**：原来单账号瞬时重试 2 次（1s/2s 退避）、逐号轮换约 30 秒即向客户端返回 502，扛不过上游 1 分钟级别的拒连/断流风暴。现在全部账号均因传输层故障失败时，退避 15 秒后**整池重扫**（最多 2 轮），把上游瞬时抖动挡在网关内侧；重扫期间一旦出现 HTTP 响应或频控，说明上游已恢复，立即按既有语义上抛——**401/429/其他 4xx 的处理路径完全不变**。

## 📊 额度（credits）实时化（网关 1.2.19）

此前看板上的剩余积分只在手动点「刷新积分」按钮、或签到/活动流程后才回读一次；看板的 15 秒轮询只是反复渲染同一份持久化旧值——打完几轮对话，余额可能几小时不动。

- **读数触发 + 单飞后台刷新**：看板每 15 秒轮询的 `GET /accounts` 顺带检查额度新鲜度，超过 TTL（默认 60 秒，`QD_CREDITS_TTL` 可调）即在后台补一次，**不阻塞响应**，下一轮轮询即见新值；
- **消耗后加速**：每次对话完成消耗额度后，该账号被标记，约 5 秒后即可触发回读——实测对话结束后 **5 秒**内余额自动更新（400 → 389）；
- **有界重试，不放大请求**：同一账号受单飞锁与最小间隔（5 秒）约束，刷新失败不会跟随轮询频率放大；停用账号按 5×TTL 低频补一次；
- **按区域过滤**：看板当前视图是哪个区域就补哪个区域的账号，`realm=all` 时全部；
- 手动「刷新积分」按钮与签到/活动后的刷新路径保持不变，仍是强制回读。

## ✅ 验证

- 单元级：额度刷新 6 项场景（过期 / 未取过 / 消耗后脏标记 / 停用账号 / 按区域过滤 / 单飞并发）全部符合预期；
- 行为级：进程内注入死代理可精确复现原始 10061 报错，清除后**下一个请求立即恢复**（旧实现需重启进程）；
- 真机（Windows ARM64 原生）：无任何手动操作下额度随轮询自动推进并按 TTL 周期刷新，对话后 5 秒余额自动更新；`--smoke-test` 的 health / models / dashboard 全绿；五平台 CI 产线全绿。
